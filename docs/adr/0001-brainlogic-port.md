# 移植 BrainLogic 游戏：双实现、弃 XP、退役旧部署

BrainLogic（E:/logic，曾部署于 logic.dokeplay.icu）的 6 个逻辑谜题游戏并入 BrainTrain，与现有 4 个反应类游戏同权：每个都有自由练习、主线闯关、多人对战三种形态。关键取舍：

- **引擎双实现**：单人部分（自由练习+闯关）的谜题引擎移植到前端纯客户端运行（可离线、成绩入 IndexedDB）；对战部分另写一份适配服务端 GameEngine 接口的引擎。这与现有 4 游戏"客户端单人逻辑 + 服务端对战引擎"的既有模式一致。因此同一游戏引擎在 brain-train/ 和 server/ 各有一份，找谬误/说得通吗题库也前后端各存一份——这是有意为之，不是重复代码事故。
- **丢弃 BrainLogic 的 XP/四维雷达体系**：BrainTrain 无 XP，进度只靠闯关星级、训练记录、连续打卡、每日目标。移植游戏不引入第二套进度体系，故代码里找不到雷达图和等级公式是刻意的。
- **闯关用尝试次数制而非限时**：谜题不限时，每关 3 次作答机会，按第几次答对评 1–3 星。
- **对战为同题竞速一次作答**：双方答同一题、仅一次作答机会、答错即锁；都对快者胜，都错平局。难度由房主选档。
- **BrainLogic 整体退役**：logic.dokeplay.icu 弃用，服务器上的用户数据（XP/进度/答题记录）直接丢弃不迁移——XP 体系已弃且 BrainTrain 单人数据在客户端，无可迁入之处。

**Considered options**: 单人部分也曾考虑服务端权威（复用 BrainLogic 的出题判题 service）和抽共享引擎包（monorepo），分别因破坏单人离线模式、仓库重构侵入性过大而否决。

**Consequences**: 修改谜题逻辑时要同步改两份引擎；服务端多人对战端口部署需手动（scp + pm2 restart braintrain-server）。
